# 每日更新机制

每天北京时间 09:45 由本对话的 Codex 定时任务执行。内容通过核验后更新 GitHub Pages，浏览站点无需登录。调度依赖本机 Codex 运行环境与网络；访问静态站点不触发采集。

## 时间与排序

- 日常检索最近七天的首发或修订，覆盖索引延迟；距上次完成日期额外重叠三天，停机后补查间隔内的内容。
- 首次执行及距上次完整回查满七天时，回查近六个月，并检查全部已登记模型家族、正式会议和引用线索。关键旧作仍可收录。
- 网站默认按论文最早已核实的公开日期从新到旧排列，支持反向排序。`updated` 只记录论文修订时间；补录时间不改变论文首发时间。同日论文按标题排列，只有年或月时保留原有日期精度。

## 每日执行

1. **准备。** 读取 `AGENTS.md`、`research/COLLECTION.md`、来源配置、模型家族表与筛选记录。检查 Git 状态和远端：工作区干净时使用 `git pull --ff-only` 同步；有未提交修改时先保留并辨认归属，不覆盖、不强推。检查 `work/collection/daily-state.json` 和以往未完成的运行记录，同一天已完成且没有失败重试事项时不重复执行。
2. **采集。** 运行 `npm run collect:daily`。脚本计算时间窗口，自动检查全部已配置的正式会议／期刊、arXiv、全文索引、六个方向的语义近邻和双向引用来源，将执行计划及候选保存在 `work/collection/daily/日期/运行编号/`。正式会议扫描当年与上一年的完整官方目录及摘要，保留轨道、录用信息和缺摘要计数。退出非零或 `incomplete: true` 都代表来源失败或截断，记录并补查，不能视为没有新论文。保留未完成运行目录中的待处理候选，不因下一次窗口前移丢弃。
3. **补查。** 每天补查自动采集的失败来源、缺失摘要、全文尚未索引的候选，以及六个方向的网页检索、已登记模型的官方版本动态、会议展示标记。对以往尚有 `nextCursor` 的 OpenAlex 报告，用 `npm run collect -- --resume 报告路径 --channels fulltext --max-pages 1 --output 本次目录/续查.json` 分批推进，后续从新的续查文件继续；预算不足则保存进度，不反复从第一页开始。从新论文的方法正文、相关工作、基线表和参考文献追踪未知家族。主题、方法同义词、模型简称和作者线索交叉搜索。语义和引用结果不得因不含原检索关键词而自动丢弃。每七天完整回查还要逐项核对全部家族、人工作者来源和自动会议覆盖；新增会议和来源加入配置。社区清单只作线索，聚合索引的会议字段不等于录用证明。
4. **核验与收录。** 按收录规则核对论文身份、首发日期、方法与实验背景、发表状态、官方代码及 PDF；更新中文概览、别名、主分类和跨方向关联。重要新模型与跨方向论文阅读方法、实验和参考文献。同一论文合并不同来源，有独立贡献的模型版本分别保留。每个已处理候选在 `research/decisions.json` 记录收录／已有／暂缓／排除及理由；不确定的留待核验，不自动补写结论。不得为凑每日数量添加论文。
5. **检查并发布。** 有已核实的新增或更正时更新 `data/papers.json`、家族登记及必要的来源／决策记录，再运行 `npm run check`；检查新条目的目录、别名检索、时间排序和原文／PDF／代码链接。只提交本次相关修改并推送当前站点的 `origin/main`，使用 `git remote get-url origin` 确认目标。等待 Pages 完成发布，核对线上 JSON 和页面。遇到推送冲突、测试失败或部署失败保留现场并报告，不重置远端、不强推。没有内容变化时不修改目录 `updatedAt`，不制造空发布。
6. **记录完成。** 在本次运行目录保存 `review.json`，写明实际核验来源、候选处理数、新增／更正的论文 ID、暂缓项、失败项、验证结果和发布结果。有未完成的来源检查或验证失败时不推进检查点。已完成检索与核验、必要发布已验证后，再原子更新 `work/collection/daily-state.json` 的 `lastCompleted`；完整回查完成时同时更新 `lastBackfill`。没有新论文但检索已完整完成，也可以推进检查点。暂缓候选保留理由和后续复查条件。

## 检查点

检查点仅记录实际完成日期，使用北京时间的 `YYYY-MM-DD`，不提交到公开目录：

```json
{
  "lastCompleted": "YYYY-MM-DD",
  "lastBackfill": "YYYY-MM-DD"
}
```

`lastBackfill` 是最近一次完成六个月回查的日期，不能晚于 `lastCompleted`。没有检查点时自动执行首次完整回查；采集脚本本身从不推进检查点，防止把抓取成功当成研究与发布成功。

```sh
npm run collect:daily -- --dry-run
npm run collect:daily
npm run check
```

## 发布边界

- 站点使用团队中性的名称和说明，不添加维护者署名或个人主页链接；收藏仍为浏览器本地功能。
- `updatedAt` 表示论文目录内容的更新，不代表最后一次检索；论文卡片的日期表示首发，不代表入库。
- 保留六大类完整标题和已有条目 ID，不恢复“优先阅读”或“验证与边界”。
- GitHub Pages 沿用当前仓库配置。执行过程、待核验候选、本机路径和调度记录保存在忽略跟踪的 `work/` 目录，不放入公开论文元数据。
