# 工作日更新机制

每个工作日（周一至周五）北京时间 09:00 由 Codex 定时任务触发；收录标准和质量审核见 [检索与收录规则](COLLECTION.md)，本文件只写执行顺序。调度依赖本机 Codex 环境与网络，实际完成时间取决于检索和审核；访问静态站点不触发采集。

周六、周日不采集、不入库、不推送站点，也不发送或补发飞书小报。周一合并补查周六、周日、周一及各渠道自上次成功运行以来的缺口，统一发布一次站点更新和小报。启动、发布和发送前均核对北京时间；跨入周末的未完成任务保留现场，周一继续。周末不生成空运行、不推进检查点；每 7 天到期的任务顺延至首个工作日执行。

执行预算及减少重复工作的规则见 [增量检索与审核预算](EFFICIENCY.md)。结果优先，已有证据确实覆盖的重叠环节可以省略；批量和参考时间不限制有价值的收录。本规则取代旧的每日九项全覆盖要求。

## 检索节奏

每个渠道单独记检查点（`work/collection/daily-state.json`）；一个来源失败只影响它自己，其他来源继续。短时限流保留缺口；明确的月度配额耗尽则冷却到供应商给出的重置日期。

| 渠道 | 频率 | 时间窗口 | 执行方式 |
| --- | --- | --- | --- |
| arXiv（主题检索式 + 已登记家族） | 每个工作日 | 最近 7 天，并与上次完成日期重叠 3 天 | 自动 |
| OpenAlex 全文 | 每个工作日；每 7 天到期后的首个工作日扩大回查 | 日常最近 7 天并补齐缺口；回查近 6 个月 | 自动，独立于 arXiv |
| 网页九项完整补查 | 每 7 天到期后的首个工作日；其他日按候选定向查 | 最近 7 天及检查点缺口，未审候选继续处理 | Codex 网页工具，必须保存证据 |
| OpenAlex 语义近邻、引用网络 | 每 7 天到期后的首个工作日 | 近 6 个月（按发表日期过滤，索引有延迟） | 自动 |
| 参考文献与官方仓库链接 | 每 7 天到期后的首个工作日 | 配置来源当前内容；保留旧作线索 | 自动 |
| 正式会议完整目录 | 每 7 天到期后的首个工作日 | 当年与上一年目录；工作日网页补查新增线索 | 自动 |
| Consensus | 每 7 天到期后的首个工作日 | 近 6 个月 | Codex 连接器，手动导入 |
| 已登记模型家族官方来源 | 每 7 天到期后的首个工作日 | — | `npm run fetch:sources -- --families` |

首次执行或渠道没有记录时回查近 6 个月；停机后从上次完成日期补齐。OpenAlex 翻页需要免费 key，写在项目根目录被忽略的 `.env`（`OPENALEX_API_KEY=...`），没有 key 时只取第一页并记为未完成。

推理效率是固定跟踪内容：周完整补查时在 `web-inference` 中分别检查表格 OOM／延迟／吞吐优化与可借鉴的 LLM 方法，按 `web-sources.json` 的 `stageQueries` 逐阶段搜索并保留实际记录；其他工作日按新候选涉及的阶段定向查询；`web-formal` 同时补查相关系统会议。LLM 方法不强制匹配 tabular 关键词，按 [推理显存与速度专题](COLLECTION.md#推理显存与速度专题)核对迁移条件和效率证据。扩充检索方向不改写已有渠道检查点；下一次正常半年回查补查新方向的历史工作。

## 每日步骤

1. **准备。** 读 `AGENTS.md`，先按北京时间检查执行日和临时安排；周末即停止，不运行采集、入库、发布或飞书补发命令。工作区干净时 `git pull --ff-only`；有未提交修改先辨认归属，不覆盖、不强推。
2. **采集。** `npm run collect:daily`。到期的自动渠道写入 `work/collection/daily/日期/运行编号/candidates-渠道.json`，完成各渠道后一次并入跨天待审队列。脚本最后列出今天到期的补查渠道（完整网页补查、Consensus、模型家族）及命令；照做后把结果并入同一运行目录。一次检索实际覆盖多个议题时共享记录，只补未覆盖项，不为逐项打勾重复查询。

   **计划中 web 到期时执行九项完整补查。** 按 `research/web-sources.json` 用网页搜索与打开工具检查六个方向、正式会议、TabArena 和相关工作；访问官方仓库、作者发布页和会议正文，使用不同术语和摘要／正文中的模型简称，不只查题名。周一检索范围包含周末与周一，并补齐各渠道缺口。将实际检索式、证据链接、已有／待审／无相关结果及失败原因写入本轮 `web-report.json`，候选用 `npm run queue -- add 本次目录/web-report.json` 合并。收尾检查九项记录，缺项不能推进网页检查点。完成清单只代表本轮有限补查，不代表穷尽全网。未到期日按 EFFICIENCY.md 定向补查，保存 web-targeted.json 并导入队列，不推进完整网页检查点。

   **失败不终止当天工作。** 自动渠道逐个独立执行；进程崩溃或队列导入失败也保存报告并继续其余渠道。非零退出表示部分缺口，随后仍执行网页补查、待审队列、质量审核与必要发布。OpenAlex 全文、语义和引用共用同一供应商，不算三个独立备用来源。API 失败不代表论文网页不可读；正文可找会议／出版社版本、作者主页和官方仓库，不绕过权限限制。
3. **初筛。** `npm run queue -- packet --output 本次目录/review-packet.json` 生成紧凑初筛包：题名命中、被多个独立渠道发现、近期首发在前，已有论文只在出现新修订或录用记录时进入"更新核对"。排序不删除候选；语义和引用结果不因缺少关键词被丢弃。先处理高分项；只在摘要命中一次的低分项每周集中扫一遍。摘要级结论用 `npm run queue -- screen-batch 初筛结果.json` 批量记下，次日不再出现，论文有新修订时自动重开。初筛记录不是公开决定。
4. **审核。** 拟收录或涉及方法／实验结论的更正，用 `npm run fetch:sources -- jobs.json --out 本次目录/primary` 取得正文文本（arXiv 优先用 HTML 版），按规则的"质量与价值审核"阅读并判断；仅摘要不能完成审核。从新论文的相关工作、基线表和参考文献追踪未知家族；TabArena 作为专项线索。
5. **写入。** 把本次新增、更正、暂缓、排除写进一个 `本次目录/review-input.json`（格式见 `scripts/apply_review.py` 开头；新增和更正各附一句 `brief`），运行 `npm run apply:review -- 本次目录/review-input.json`。脚本校验质量审核字段，统一写入 `data/papers.json`、`research/decisions.json` 和家族登记表。不要为这些步骤另写一次性脚本。不得为凑数量添加论文。
6. **检查并发布。** `npm run record:updates && npm run check`，再在站内按目录、年份和简称搜索新条目。只提交本次相关修改，推送 `origin/main`（先用 `git remote get-url origin` 确认），等待 Pages 发布后核对线上 JSON 与页面；截图核对只在本次确有发布时做。推送冲突、测试或部署失败时保留现场并报告，不重置远端、不强推。没有内容变化时不修改 `updatedAt`，不制造空发布。
7. **收尾。** 有新增或更正时，先按["今天的看点"撰写提示词](BRIEFING_PROMPT.md)写 `本次目录/briefing-highlights.md`，再运行 `npm run collect:finish -- 本次目录 --review-input 本次目录/review-input.json [--published] [--note 缺口说明]`。脚本生成固定格式的 `review.json`、小报 `briefing.md` 和运行记录 `run-notes.md`，并只推进本次完整完成的渠道检查点。候选已在队列里，所以检索检查点与审核进度分开推进，未审候选不会丢失。发布或核对未完成时不加 `--published`。
8. **群内发布。** 本机已配置飞书发送时，`collect:finish` 自动调用 `lark-cli`，将已上线的小报和站点链接发布到获授权的话题群，并回读核验；同时重试启用日期以来尚未送达的小报。周一的周末合并收集只生成一次本期小报，不按周末逐日补造小报。通知失败保留回执，收录检查点不回退。补发可在允许的工作日独立运行 `npm run briefing:send`，无需重跑检索；周末不补发。

```sh
npm run collect:daily
npm run queue -- top
npm run apply:review -- 本次目录/review-input.json
npm run record:updates && npm run check
npm run collect:finish -- 本次目录 --review-input 本次目录/review-input.json --published
```

## 更新小报与运行记录

`collect:finish` 每次生成两份文件，结论和过程分开：

| 文件 | 何时生成 | 内容 |
| --- | --- | --- |
| `briefing.md`（小报） | 有新增或实质更正时 | 只写结论。开头一句速览（自动）：收录篇数、新论文与补录各几篇、覆盖哪些方向、论文库链接。"今天的看点"：审核者按[撰写提示词](BRIEFING_PROMPT.md)写入 `briefing-highlights.md`，用 150–300 字平实地讲清今天的主线和两三篇重点论文。各方向上新（自动）：按方向分组，每篇一行简称、链接和 `brief`。 |
| `run-notes.md`（运行记录） | 每次 | 过程信息。需要处理的问题：检索失败渠道、未上线、`--note`。暂缓论文及理由。渠道完成情况、待审队列规模、发布状态。 |

在当前对话里先输出小报全文和文件链接。只有运行记录的"需要处理"一节有内容时，才另起一段简短列出问题。没有新增也没有问题时保持安静。获用户明确授权后，只向本机飞书配置指定的话题群自动发送公开小报和站点链接；不发送运行记录、候选、内部备注、本机路径或聊天内容，不向其他接收方发送。

小报标题中的日期使用实际更新日，沿用现有标题及自动生成流程。周一或其他合并更新时，在“今天的看点”首句简要注明实际覆盖期间，再介绍论文；论文首发日期不因合并更新改变。没有实质新增或更正，不生成或发送空小报。

## 飞书小报发送

- 通过已安装的 `lark-cli` 发送 Markdown 富文本。每次实质更新创建一个新话题，保留论文原文链接和网站入口；无更新不发空小报，不自动 @ 群成员。
- 发送与补发只在允许的工作日执行；周末保留未送达回执，到下一工作日再按原幂等键回查、重试，不另建重复话题。
- 目标与身份仅保存在 Git 忽略的 `work/notifications/feishu.json`：`enabled`、`identity`（`user` 或 `bot`）、`chatName`、`notBefore`（启用日期），首次精确匹配唯一话题群后写入 `chatId`。不按模糊名称自动选群，不自动切换身份。凭证由飞书 CLI 管理，不写入仓库。
- 用户身份须完成飞书授权；机器人身份须具备权限并已加入目标群。身份失效或目标不匹配时停止发送，在当前对话报告处理方式。
- 只发送 `publication.published=true` 的运行，发送前再次核对本次论文线上与本地一致。只读取该运行的 `briefing.md`，核对日期及论文链接覆盖。
- 按群、北京时间日期和论文 ID 清单去重；回执保存在 `work/notifications/receipts/`，成功回读后也保存到运行目录的 `feishu-delivery.json`。同一清单正文变更不另发重复话题，先核对已有消息。CLI 请求使用固定幂等键；网络结果不明时先回查群历史，超过安全重试窗口不盲目重发。
- `npm run briefing:send -- --run 本次目录 --dry-run` 预览；去掉 `--dry-run` 发送该次小报；不传 `--run` 重试启用日期以来尚未发送的已发布小报。换机器时需迁移本机配置和回执，或设置新的启用日期，避免补发历史内容。

每篇新增或更正在 `review-input.json` 里附 `brief`（不超过 80 字，说明它是什么；更正写明改了什么），可选 `name` 指定简称。`apply:review` 会检查 `brief`。

## 检查点格式

```json
{"channels": {"arxiv": "YYYY-MM-DD", "fulltext": "YYYY-MM-DD", "semantic": "YYYY-MM-DD", "citations": "YYYY-MM-DD",
              "formal": "YYYY-MM-DD", "references": "YYYY-MM-DD", "consensus": "YYYY-MM-DD", "families": "YYYY-MM-DD"}}
```

日期为北京时间，记录渠道最近一次实际完整完成。只有 `npm run collect:finish` 根据运行目录中的报告推进检查点；采集命令本身从不推进。周末、临时跳过日及失败渠道均不得虚进检查点；周一或合并更新从各自原检查点补查，只推进本次实际完成的渠道。

## 资源使用

- 网络缓存保留两天，采集时自动清理；同一天重试复用缓存。
- 会议完整目录、OpenAlex 半年回查、Consensus 与全量家族核对按每 7 天计算到期，在到期后的首个工作日执行；工作日增量和按需网页补查独立执行。
- 明确配额重置时使用 `npm run collect:daily -- --defer-channel consensus --retry-after YYYY-MM-DD --reason 供应商提示`；只记录冷却，不推进检索检查点，到期后的首个工作日补查。普通 429 不自动视为月度额度耗尽，不伪造恢复日期。
- `daily-state.json` 的 `backfills.fulltext` 独立记录半年回查日期，避免每日成功把周回查无限推迟；`cooldowns` 保留暂不可用来源及恢复日期。
- 正文抓取只保存文本和 SHA-256，需要原件时加 `--keep-raw`。

## 日期与发布边界

- 论文卡片顶部日期是最早已核实的公开时间，`updated` 是论文修订时间，`addedAt` 是首次加入本站的北京时间日期；三者分别维护，更正不改写 `addedAt`。`collectionUpdates` 按日记录新增与资料更新，同日去重，由 `npm run record:updates` 维护。
- 目录 `+N` 和"今日收录"按当天 `addedAt` 自动显示，跨北京时间零点清除，无需手动维护。
- `updatedAt` 表示目录内容更新，不代表最后一次检索。
- 站点保持团队中性名称，不加个人署名；保留六大类完整标题和已有 ID，不恢复"优先阅读"或"验证与边界"。
- 执行过程、候选、队列、检查点和本机路径只保存在被忽略的 `work/` 目录，不进入公开元数据。
