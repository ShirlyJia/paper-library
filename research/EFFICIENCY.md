# 增量检索与审核预算

自 2026-10-29 起，用每日增量发现、每周完整补查和按需正文审核替代每日重复全覆盖。结果优先：及时发现有价值的研究、完成可靠收录、上线并送达小报。范围和质量门槛仍以 COLLECTION.md 为准；时间、查询数和批大小仅用于组织工作，不能作为停止有价值工作或压缩成果的配额。

## 信息重叠时直接复用

- 一次检索或一份一手资料实际覆盖多个方向时，共用该证据，不为每个目录重新搜索。记录实际覆盖范围和原查询即可，不能把同一来源算作多份独立证据，也不能借此推进失败接口的检查点。
- 同一论文、同一版本已核实的事实直接复用；定位新版本的差异、冲突和缺口后再补读。没有变化证据时无需重复下载、阅读和改写整份审核记录。随时间变化的录用、版本和榜单信息仍需查当前来源。
- 证据记录引用已有文件及章节位置，只补本轮新增信息；多渠道命中只合并来源，不重复审核、计数或生成说明。
- 同一最终内容版本通过的检查可复用；有相关修改才重查受影响部分。实际发布后的线上一致性与飞书送达核验仍需完成。

## 1. 每日发现

- 工作日执行 arXiv、OpenAlex 增量，保留最近七天及检查点缺口。自动结果集中合并一次队列；失败来源独立保留。
- 网页九项完整补查、六个推理阶段与官方参考文献列表改为每七天到期后的首个工作日执行。正式会议、家族、语义和引用网络继续按周检查；半年回查不取消。
- 非完整补查日，网页只服务于新候选、版本变化、待审资料和来源故障。通常先用 2–4 条定向查询，复用自动采集线索，不再逐项重复泛词搜索。两条主渠道都不可用时，至少补查模型官方发布、正式会议和 TabArena，结果保留到队列。
- 定向补查记录为 web-targeted.json 并导入队列，不冒充完成九项覆盖、不推进完整网页检查点。周回查未完成则保存记录继续，不将部分完成写成完整。
- 普通失败当轮最多补试一次；月配额冷却至明确恢复日期。失败记录不丢，不能因为重试失败而回退成功渠道。

## 2. 紧凑初筛

运行 `npm run queue -- packet --output 本次目录/review-packet.json`，默认先向审核者提供 20 条排序候选及 5 条较早积压条目的题名、摘要、日期和来源。有高价值候选时扩大批次或继续处理，不把初筛包大小当作当天上限。不把整个队列、旧审核全文或搜索原始输出放进模型上下文。

先判断是否有明确技术关联、是否同一论文/新版本、是否值得取正文。初筛写成 JSON 数组（id、verdict、reason），用 `npm run queue -- screen-batch 文件.json` 一次落盘；verdict 为 not-relevant 或 needs-fulltext。前者必须有实际阅读的排除理由，不能仅因缺关键词排除；后者保持待审。积压条目须记录结论，避免每天反复扫同一批。

## 3. 按需正文审核

- 日常可先以 3 篇为一批组织正文审核，按候选价值和实际证据继续追加；从积压中选有价值线索初筛，避免只跟热门标题。30 分钟日常／60 分钟周补查仅作为检查重复开销的参考点，不是停止条件，也不是计费或平台 token 硬上限。
- 有明确价值且资料齐备的候选继续审核，不因到达参考时间就延后。仅对暂缺关键证据、反复失败或继续探索收益低的部分保存已读范围、剩余问题和恢复条件，下一工作日继续。已核实内容及时完成检查、发布和发送；不为凑篇数添加论文，不为赶时间省略方法/实验审核。
- 已有版本的正文及审核记录优先复用；同一论文只选一个可读一手全文。确有新版本、关键冲突或表格提取缺失才读补充版本。先按小节定位方法、实验、划分和核心表格，必要时扩展阅读；不能仅凭摘要完成审核。
- 只改链接、日期、会议标签时核对对应来源，勿重读全部实验或冒充重新完成质量审核。LLM 迁移研究必须说明具体阶段与迁移条件。

## 4. 一次收尾

- 同一批内容整理完，统一运行 record:updates 与 check。测试通过且内容未再变，不重复全套检查。
- 纯论文数据更新：按新增主目录检查、抽查一个简称和年份筛选；发布后核对 Pages 提交、一次完整 JSON 比对及一次页面/新增标记检查。仅前端改动才扩展交互测试；不为每篇反复打开同一页面。
- 生成一份 briefing.md；对话与飞书使用同一份内容。保留既有幂等键、回读和未送达重试；只发公开小报。流程优化本身不生成论文小报。
- run-notes.md 另记开始/结束时间、本轮初筛/正文审核篇数、使用的网页查询数、延期原因。没有真实 token/费用数据就不估报节省比例。观察一周后按新增价值、积压增长和耗时调整预算。
