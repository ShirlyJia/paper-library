# 论文检索与收录规则

以现有六个领域为浏览目录；检索同时沿主题、模型家族、正式会议、作者发布和引用关系展开。近半年新作重点覆盖，关键前作和方法来源保留。

## 收录范围

- 直接涉及表格／关系数据基础模型、结构化预测与决策的模型、算法、适配、推理、因果和语义结构化研究。
- 模型论文即使包含预训练，经核验后仍可收录并解释其架构、推理或适配贡献；“不重点研究预训练”不作为整篇排除条件。
- 不为每类设置固定篇数，不因已有代表作或版本较旧删除不同工作。新版模型与有独立贡献的旧版分别收录，同一论文的预印本／会议版／更名版本合并。
- 官方技术报告、模型卡和架构说明可收入业界类，明确标识来源类型；不得冒充正式会议论文。只有产品名而缺少技术资料的线索保留在待核验记录中。

## 每次检索

1. 运行 `npm run collect`：搜索 arXiv 的题名、摘要及其他元数据，扫描已配置的 PMLR 完整会议目录，并提取种子论文参考文献、官方仓库和 Workshop 页面中的论文链接。默认覆盖近六个月的首发或修订；引用追溯不受时间窗口限制。
2. 按 `model-families.json` 逐家核对官方仓库、模型卡、报告与版本沿革；每个新模型都补其别名、前作和相关版本。新发现的家族加入登记表，不能只检查已知名单。
3. 补查 `sources.json` 的人工来源：NeurIPS、ICLR、TMLR、ACL 录用目录，以及作者／机构发布页；并从综述和模型对比表反查漏掉的基线。社区列表、搜索引擎和新闻仅提供线索，技术内容及收录状态回到一手来源确认。
4. 阅读候选的原始摘要；对新模型和跨方向工作进一步看方法、实验及参考文献。记录收录、已有、待核验或排除及理由。模型简称常不在论文题名中，须搜索摘要、代码仓库和全文中的方法名称。
5. 按 arXiv ID、DOI、OpenReview ID、正式页面和规范化题名合并候选；同名不同论文不强行合并，改题名工作保留来源映射。核实首发、修订、正式发表三种日期；会议年份不能替代首发时间。
6. 更新 `data/papers.json` 和家族登记表，运行 `npm run check`，检查新条目的别名搜索、目录归属、来源／PDF／代码链接，确认后发布。

## 采集命令

```sh
npm run collect
npm run collect -- --since 2026-04-12 --until 2026-10-12
npm run collect -- --refresh
```

采集器只需 Python 3 标准库，无付费 API 或登录。输出位于 `work/collection/latest.json`，不直接写入公开目录。每条候选保留发现渠道、原始摘要、来源及是否已收录；已有条目仍进入更新核对，避免漏掉后续会议收录。

arXiv 结果自动翻页，默认最多十页／检索式。API 失败、解析失败或触及分页上限都会记录并返回非零状态，不能把缺页视为空结果或宣称检索完整。网络响应只缓存一天；`--refresh` 强制重新请求。

自动采集不等于完整研究：未配置站点、没有可提取链接的参考文献、搜索尚未索引的新作，以及模型卡中的非论文更新，需要第 2–4 步补查。每轮记录实际完成的渠道，不声称穷尽所有论文。

已完成的筛选记录存入 `decisions.json`。未决候选不会自动发布；暂缓或排除的理由会随下次采集保留，遇到较新的修订重新进入核验。首次补查见[2026-10-12 记录](review-2026-10-12.md)。

## 公开条目

- `aliases`：正式简称、原题名、产品名及常用写法，供站内搜索；不能用不相关关键词凑召回。
- `sources`：实际核验的一手来源，供去重及后续更新；主入口仍是 `url`。
- `summary`：简要说明问题、方法和技术位置，避免未经复现的质量分数或无条件“最优”结论。
- `status`、`venue`、`recognition`：分别保存预印本／报告／主会／Workshop 及经核实的展示标记。未核实录用不能写“已收录”；博客的小标题 Highlights 不是会议 Highlight。
- 一个主目录路径，`related` 记录跨领域联系；跨方向不会复制为多篇。家族登记表允许指向其他目录中的模型论文。

## 覆盖检查

`npm run check` 同时检查已登记版本是否全部在目录中、是否重复收录同一来源、别名和核验来源格式是否有效。该检查能防止已知论文在汇总时消失，不能发现尚未检索到的新作。

公开目录 `data/papers.json` 是当前唯一维护源。仓库之外早期 `work/research/build-report.py`、`prepare-library.py` 是历史清单／迁移脚本，不能用来覆盖当前目录；其中的人工排除名单和篇数控制不再适用。
